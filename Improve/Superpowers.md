# 核心
问题不在于 Agent 不够聪明——它够聪明。问题在于它不够自律  
不要期望 Agent 自律，要设计让它不得不自律的系统  
把"下限"从"取决于运气"提升到"结构化保证"
# 七重防线体系
## 强制规划门控
Agent 最常见的失败模式是"拿到需求直接写代码"，这个 Gate 物理阻断这条路径  
特别强调"包括你觉得简单的项目"——因为"这个太简单不需要设计"是 Agent 跳过规划最常用的借口  
## TDD 铁律
不是"建议写测试"，而是绝对禁令。违反后果是删除全部代码重来  
任何程度的"灵活性"都会被 Agent 利用为跳过测试的借口，只有"违反即删除"才能真正改变行为  
配套的反理性化表预先反驳了 11 种常见借口（"太简单不需要""先写后补""手动验证过了""删掉太浪费"……），让 Agent 在产生这些想法时就找不到合理化的空间
## 验证门控
直接攻击 Agent 最危险的行为——谎报完成，要求每一次完成声明必须附带新鲜的验证证据（命令输出 + exit code），不接受"应该没问题"
## 两阶段代码审查
实现完成 → Spec Reviewer（做对了没？）→ Code Quality Reviewer（做好了没？）  
顺序不可调换，如果先审质量再审规格，可能花大量时间优化一段根本不该存在的代码
## 系统化调试
Bug 出现时强制 Agent 沿调用链逆向追溯到源头，而非"哪里报错修哪里"，修复后还要加纵深防御层
## 工作区隔离
所有实现必须在 Git Worktree 隔离分支中进行，主干始终干净，Agent 的实验性代码永远不会污染生产环境
## 反理性化心理学防线
1.通过子 Agent 压力测试找出所有可能的借口  
2.在 Skill 中预先放置反驳（借口还没产生就已被封堵）  
3.用 Red Flags 教 Agent 识别自己正在理性化的信号  
4.用语言约束禁止模糊词汇（"should"/"probably"/"seems to"）
